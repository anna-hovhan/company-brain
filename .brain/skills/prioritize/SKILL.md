# Prioritize

Theory: `System/Frameworks/Effort-Impact Matrix.md`. Output: `Company/Roadmap/Company Prioritization.md` or `Teams/<Team>/<Team> Prioritization.md` (generated by `brain refresh`).

## Before you start
1. **Find the brain.** The session context has a **Company Brain** line with the brain path and the engine path. If it is missing, run `python3 "${CLAUDE_SKILL_DIR}/../../scripts/brain.py" root`. No brain found: stop and tell the user to open Claude in the brain folder or set the plugin's vault path.
2. **`brain`** below means `python3 "<engine>/scripts/brain.py" --root "<brain>"` (or `./brain` from the brain root).
3. **Read the rules** in `<brain>/CLAUDE.md` unless they are already loaded, and `Personal/Me.md` for who "me" and "my team" are. No `Me.md`: run the `setup` skill first.
4. **Write only with file tools or the `brain` CLI.** Never use the obsidian-second-brain MCP tools here; they point at a different vault.

## Steps
1. **Scope**: company or a team (default: my team). Items are open `solution` and `project` notes in that layer.
2. **Find unscored items**: no `impact:` or `effort:`. For each, propose scores with one-line rationale and ask the user to confirm or adjust:
   - Impact 1-5: expected effect on the outcome or KR it serves (link it). 5 means it moves the KR substantially on its own.
   - Effort 1-5: relative cost (people, weeks, dependencies). Calibrate against an item the team already knows.
   - Optional RICE: `reach` (people or events per quarter), `confidence` (high 100 percent, medium 80, low 50); RICE = reach x impact x confidence / effort.
3. Write the fields to each note and `brain refresh`.
4. **Read the matrix** and recommend:
   - Quick wins (high impact, low effort): candidates for Now.
   - Big bets (high impact, high effort): slice into experiments or smaller releases; Next or Later.
   - Fill-ins (low, low): backlog, do when there is slack.
   - Money pits (low impact, high effort): drop or rethink; record a decision if dropping something people expected.
5. With the user's agreement, apply the moves with `roadmap` and record significant calls with `decide`.

Scores are judgments: keep the rationale in the note (`## Scoring rationale` on solutions), and re-score when evidence changes rather than tweaking numbers to fit a preferred answer.

## Always
- Layers: Company/ and Teams/ are shared; Personal/ is local only. Never link from a shared note to a Personal note, and never copy content under `## Private` out of Personal/ (`references/layers.md`).
- AI-first notes: frontmatter with `date`, `type`, `tags`, `ai-first: true`, `layer`; a `## For future agent` preamble; `[[wikilinks]]` for every person, team, objective, and project (`references/ai-first-rules.md`, `references/schemas.md`).
- Search before create (`brain new` refuses duplicates and prints the existing path). Never invent facts, numbers, dates, or people: write `TBD` and ask.
- Finish with `brain refresh` when OKRs, discovery, scores, or people changed, otherwise `brain index`. With `sharing: git`, list the shared files changed and suggest a commit; never push or open a pull request yourself.
